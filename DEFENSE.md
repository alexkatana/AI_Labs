# Памятка для защиты: введение в прикладной ИИ

## Какие данные и задачи

- ЛР №1: основы Python, датасета нет.
- ЛР №2: разведочный анализ красного вина.
- ЛР №3: классические модели по вину.
- ЛР №4: три нейросети по вину.
- ЛР №5: классификация изображений бабочек.

Во всех работах показаны результаты реального выполнения ячеек. Точные результаты нужно смотреть в таблицах ноутбуков и CSV из artifacts.

## ЛР №3 — что сказать

«Я обучил четыре семейства моделей для предсказания оценки качества вина: логистическую регрессию, дерево решений, ближайших соседей и случайный лес. Признаки — 11 физико-химических измерений, цель — quality, наблюдаемые классы 3–8. Удалил точные повторы до разбиения. Параметры выбирал по macro-F1 на трёхкратной кросс-валидации внутри train. На test посчитал Accuracy, macro-F1, ROC-AUC и построил ROC- и PR-кривые».

### Как работают модели

- Логистическая регрессия: вычисляет линейные оценки по признакам и преобразует их в вероятности классов. Несмотря на название, здесь решает классификацию.
- Дерево решений: последовательно задаёт вопросы вида «признак меньше порога?» и приводит объект в лист с распределением классов. Большая глубина позволяет запоминать обучение.
- KNN: ищет k ближайших обучающих объектов; их классы определяют ответ. Масштабирование важно, потому что расстояние иначе определяется признаками с большими числами.
- Случайный лес: ансамбль деревьев, обученных с использованием случайности. Усредняет их вероятности. Это снижает зависимость от одного дерева, но не исключает переобучение.
- DummyClassifier: всегда отвечает наиболее частым обучающим классом. Проверяет, лучше ли модель простого базового решения.

### Что такое гиперпараметры

Настройки, задаваемые до обучения: C у логистической регрессии, глубина дерева, размер листа, число соседей. Они отличаются от параметров модели, которые алгоритм находит при обучении.

GridSearchCV перебирает заданные настройки. На каждой из трёх итераций CV обучает модель на двух частях train и проверяет на третьей. Test в поиске не участвует. Pipeline заново обучает преобразования внутри каждого fold.

### Основной результат

По CV выбран случайный лес. Test Accuracy около 54,8%, macro-F1 около 0,311; у Dummy Accuracy около 42,6%. Неограниченное дерево получило 100% на train и около 50,4% на test — переобучение. У леса тоже есть разрыв train/test. Редкие оценки распознаются плохо; отсутствие хорошего результата нельзя скрывать высокой общей Accuracy.

## ЛР №4 — что сказать

«Я сравнил линейную нейросеть, сеть с одним скрытым слоем и сеть с тремя скрытыми слоями. Для первой использовал SGD, для двух остальных Adam. Перевёл данные в Dataset и DataLoader. По эпохам записывал loss и Accuracy. Лучшие веса выбирал по validation, затем оценивал их на test».

### Архитектуры

- 11 → 6: один обучаемый линейный слой, без скрытых слоёв.
- 11 → 64 → 6: один скрытый слой и ReLU.
- 11 → 128 → 64 → 32 → 6: три скрытых слоя, ReLU и Dropout.

Выходов шесть, потому что в данных шесть классов. Оценки 3–8 переведены в индексы 0–5; это только кодировка, порядок меток не потерян. CrossEntropyLoss ожидает индексы, поэтому one-hot не нужен. Во входных данных все признаки численные.

### Термины

- Нейронный слой: преобразует входы с помощью обучаемых весов и смещений.
- ReLU: нелинейная функция max(0, x). Без нелинейностей несколько линейных слоёв свелись бы к одному линейному преобразованию.
- Логиты: численные выходы последнего слоя до преобразования в вероятности.
- Cross-entropy loss: штраф за несовпадение предсказанного распределения с истинным классом. Особенно штрафует уверенные неправильные ответы.
- SGD: обновляет веса в направлении уменьшения loss по градиенту мини-батча.
- Adam: адаптирует шаги обновления по накопленной информации о градиентах.
- Learning rate: размер шага обновления.
- Эпоха: проход по всей обучающей выборке.
- Батч: часть выборки для одного шага обновления.
- Dataset: интерфейс, возвращающий объект и его метку по индексу.
- DataLoader: собирает объекты в батчи и может перемешивать их.
- Dropout: случайно выключает часть активаций во время обучения. При проверке в eval он выключен.
- eval(): переводит модель в режим проверки; сам по себе не отключает градиенты. Для этого используется no_grad().

### Основной результат

Test Accuracy: линейная сеть около 58,5%, один скрытый слой — 62,1%, три — 62,9%. Глубокая сеть выбрана по минимальному val-loss на эпохе 35. К эпохе 120 train-loss снизился, а val-loss вырос: позднее обучение переобучает модель. Редкие классы всё ещё распознаются плохо.

## ЛР №5 — что сказать

«Я решал классификацию бабочек по изображениям. Проверил разметку, чтение файлов и точные дубликаты. Из размеченных данных выделил validation со стратификацией. Использовал предобученную MobileNetV2 как замороженный извлекатель признаков и обучил новый классификатор на 75 выходов. Применил аугментации только к train, посчитал метрики и построил матрицу ошибок и ROC-кривые. Показал примеры всех классов и десять предсказаний».

### Что означает transfer learning

Модель уже обучена на большой коллекции изображений ImageNet. Мы используем её способность выделять визуальные признаки для другой задачи. Старый выходной слой на 1000 классов заменён новым на 75. В нашей работе основной блок заморожен — его веса не меняются, обучается только новая голова. Это не полное дообучение всей сети.

Для CPU признаки извлечены заранее: чистые train-изображения, одна случайная аугментированная версия каждого train-изображения и validation. Поэтому случайные изображения не генерируются заново каждую эпоху — это ограничение реализации, явно описанное в ноутбуке.

### Аугментации

- RandomResizedCrop: случайное кадрирование и изменение масштаба.
- RandomHorizontalFlip: случайное горизонтальное отражение.
- RandomRotation: небольшой случайный поворот.
- ColorJitter: небольшое изменение яркости, контраста и насыщенности.

Они создают вариативность train, сохраняя класс изображения. Validation случайно не меняется. Нормализация использует ImageNet mean/std, соответствующие предобученной модели; это не вычисление средних по validation.

### Какие данные проверяли

В исходной размеченной части 6499 изображений и 75 классов. Есть 2786 официальных тестовых изображений без меток. По ним нельзя посчитать качество. После исключения точных повторов размеченная часть делится на train и validation; точные RGB-хеши между ними не пересекаются. Проверка хешем не гарантирует удаления всех похожих снимков.

Validation используется для выбора лучшей эпохи. Поэтому это валидационное качество; отдельного финального теста с метками у нас нет. Лучшие веса сохранены в artifacts/lab5_best_model.pt.

## Train, validation, test

- Train: данные для изменения весов или параметров модели.
- Validation: выбор настроек, эпохи и архитектуры.
- Test: финальная проверка зафиксированной модели на отложенных объектах.

В ЛР №3 роль validation выполняют внутренние CV-folds. В №4 выделена отдельная validation из внешнего train. Test-loss по эпохам выводится по требованию задания, но не влияет на выбор. В №5 отдельного размеченного test нет, поэтому выводы ограничены validation.

## Что такое утечка данных

Использование при обучении информации, которой не должно быть доступно: например, одинаковое изображение одновременно в train и validation или масштабирование по всей таблице до разбиения. Это может завысить оценку качества. Поэтому сначала разбиение, затем обучение преобразований только на train.

## Метрики простыми словами

- Accuracy: доля правильных ответов. Из 100 объектов правильно определили 60 — Accuracy=0,60.
- Precision класса: какая доля предсказаний этого класса правильная.
- Recall класса: какую долю реальных объектов этого класса нашли.
- F1: гармоническое среднее Precision и Recall, 2PR/(P+R). Высок только когда оба показателя достаточно высоки.
- Macro: посчитать метрику каждого класса и усреднить с равными весами. Редкий класс важен так же, как частый.
- Micro: объединить все решения. В обычной многоклассовой задаче с одним ответом на объект micro-F1 совпадает с Accuracy.
- ROC-AUC: насколько хорошо вероятности ранжируют положительные объекты выше отрицательных в задаче «класс против остальных». Это не доля правильных предсказаний.
- Average Precision: сводный показатель PR-кривой. Особенно полезен при редких положительных объектах.

## Названия графиков

| График | Оси и смысл |
| --- | --- |
| Кривая обучения | X — эпоха, Y — loss или Accuracy. Показывает ход обучения, разрыв train/val, признаки переобучения. |
| ROC-кривая | X — FPR, доля ложноположительных среди отрицательных; Y — TPR, доля найденных положительных. Точки соответствуют разным порогам вероятности. |
| PR-кривая | X — Recall, Y — Precision. Показывает компромисс полноты и точности при изменении порога. |
| Матрица ошибок | Строки — истинные классы, столбцы — предсказанные. Диагональ — верные ответы; вне диагонали — ошибки между конкретными классами. |
| Столбчатая диаграмма классов | Класс и количество его объектов. Показывает дисбаланс. |
| Примеры предсказаний | Фотография, истинный и предсказанный классы. Y — верно, N — ошибка. Примеры иллюстрируют результат, но не заменяют метрики всей выборки. |

## Переобучение и недообучение

Переобучение: модель хорошо запомнила train, но заметно хуже обобщает на отложенные данные. Типичный признак — train-loss падает, val-loss растёт. Помогают регуляризация, уменьшение сложности, ранняя остановка и дополнительные данные.

Недообучение: модель не отражает существенные зависимости даже на train. Причиной может быть недостаточная выразительность, недостаточное обучение или плохая оптимизация. Низкое качество на редких классах само по себе ещё не доказывает недообучение.

## Почему результаты не 100%

Признаки не определяют целевую оценку однозначно, данные ограничены и несбалансированы, классы могут быть похожи. 100% на обучении не означает хорошую модель. Мы показываем фактические результаты и ограничения, а не подгоняем тест.
